# In-game acceptance checklist: remaining scope

The user accepted the Guardian panel screenshot, including the broad glow, and the custom icon in the local client. The checks below remain a broader regression checklist; screenshot acceptance does not establish all-client, Paladin, combat/taint or performance acceptance, or a public release. SavedVariables are outside installation scope.

- Confirm `/dump GetBuildInfo()` reports a compatible Retail interface and the addon loads without Lua errors.
- With a valid target, check fixed 0–2000 labels on all four rows through refresh, specialization changes, zero and extreme values. Own/target values above 2000 must retain their numbers plus >; a partially or wholly offscale P40/P60 band must show its overflow status and real endpoints in the target tooltip. Confirm the DR notch is absent (including its bar hit target) and check the retained DR label against the user-supplied guides (1380/1320/1380/1620), including coincidence with the vertical target marker. DR must disappear outside level-90 Retail interface 120100 or without a valid target. Verify both languages explain first DR onset, continued lower incremental benefit and excluded percentage buffs; these are guide values, not caps or optimal targets. Recheck compact layout and tooltip reachability in both skins. Independent provenance verification is separate from this visual gate.
- Check the broad static stat-colored halo in both skins: full identical intensity in-band and above, none below the band or for zero/unknown/invalid comparison. Native white-texture gradients extend nine physical pixels outside the filled bar at tall layout height, tapering to three pixels at minimum height. Four edges and six gradient strips per corner soften the complete perimeter; no external asset, input frame, animation or polling is added. Layout reserves the larger of marker ink and halo radius plus text clearance. Verify soft falloff (not just bright outlines), corners at short/full fills, clear target/band ink, adjacent labels at minimum height and unchanged tooltip reachability. The Guardian screenshot has user acceptance; the remaining skin/layout combinations still need native checks. Mock geometry alone is not visual approval. This is decorative emphasis, not a performance recommendation.
- Open Character → equipment: exactly one attached panel appears with current Crit, Haste, Mastery, Versatility in that order. Check native glyphs, spacing, clipping, and anchor position at the user's UI scale.
- Confirm the smaller +/− sidebar sits higher, below the close X and above the equipment tab strip, inside CharacterFrame's right edge. Check both collapsed states and host/UI scale changes; it must neither cover Ausrüstung nor intercept the close button.
- Switch Character tabs and close the window: panel disappears; reopen equipment and verify current values are refreshed once. Repeat after gear changes and specialization changes.
- While visible, switch Default/Flat dark and collapse/expand with the +/− sidebar button. Reload UI and verify persistence. Confirm both mode buttons are absent, comparison is M+ only and Reset restores Mythic+/Default/expanded. Verify the sidebar is reachable while collapsed and hidden on other tabs. Confirm flat dark removes native background/button textures and switching back restores them.
- On deDE and enUS clients, inspect every label and the unknown-data message. Confirm English fallback on any other locale.
- Check the active specialization name without an ID, current rating, target and below/in/above labels, explanatory tooltip, button hover/selection colors, and both skins at the user's font scale. The unavailable ratingTarget snapshot must show only readable current ratings, with no target labels or graphics. Checking four readable rating bars in Crit/Haste/Mastery/Versatility order, one target marker, P40 to P60 band and date/sample summary requires a valid authorized rating fixture/provider with verified rating targets; synthetic fixtures are not live cohort evidence. Compare the panel's physical top and bottom with CharacterFrame, especially at about 424 native CharacterFrame units and 1.76 effective scale. Move and resize CharacterFrame, change UI scale, and move it near both screen edges and the bottom edge; verify the attachment remains visible without clipping when the viewport can fit it. With the valid rating fixture/provider, recheck fill and marker positions after width changes without a stat event.
- Open Options > AddOns > Stat Compass directly after login, before opening Character. Check the skin selector, minimap visibility and appearance reset. Change the inline skin, reopen Options, and verify both read the same saved value. Switch categories and close/reopen with ESC; no duplicate canvas or separate window should remain.
- Left-click the minimap icon from closed equipment and another Character tab; it should open equipment, not toggle it closed. Right-click should open the native category. Drag at UI/minimap scale extremes, then /reload and check its angle. Hide the minimap during a drag and confirm there is no lingering update callback; hide/show the icon through Options and reset it. Confirm the bundled custom icon and client mask render and German/English tooltips fit. Mock coverage does not prove in-game rendering or combat/taint safety.
- Confirm target labels and graphics remain hidden with the repository’s empty Data.lua and the unavailable message is readable. A readable current rating may remain; an unknown rating must not look like zero.
- Exercise equipment/stat events while hidden and visible, including combat-safe behavior; check for errors, delayed stale callbacks, frame growth, native Character panel lifecycle, and interaction with other UI skins.
- If authorized cohort data is later supplied, verify actual EU top 30 selection per specialization and Mythic+ context; exact client build and interface, season/ranking metric/difficulty/partition, mastery-effect units, observed/collected/expiry times, counts, source rights, status/deletion duties, and retention/revocation workflow. Compare target and P40/P60 endpoints with the producer snapshot. Check own values below, at and above both endpoints; endpoints must read “passt” / “fits”. Check zero and a current value above the target band. Confirm Prio is localized, uses the supplied budget-investment order and its tooltip disclaims simulation. Verify cohort median percentages and the exact combined-budget warning against the same snapshot. Current pure-rating targets omit personal and must not show a missing-conversion warning; only legacy personal=false payloads retain that note. Perform separate comparable in-game profiling; no ms/FPS claims follow from the mock tests.
