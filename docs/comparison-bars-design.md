# Rating comparison bars

This is a UI-only presentation contract. `Core.lua` still supplies percent points in `snapshot.current` and `snapshot.target`; neither is interpreted as rating. Shipped `Data.lua` is empty. The separate Blizzard provider already extracts ratings and rating ranges into its report, but the inspected Core snapshot does not expose the following UI interface or an authoritative rating cap. A producer must explicitly supply `snapshot.ratingComparison[stat]` for each of `crit`, `haste`, `mastery`, and `versatility`:

```lua
{ currentRating = 800, axisMaxRating = 2000,
  axisVerified = true, axisProvenance = "source and method establishing attainable rating cap",
  reference = { minRating = 300, meanRating = 600, maxRating = 700 },
  sampleCount = 27, sourceStatus = "verified" }
```

All numeric fields are public, finite rating points. The axis is `0..axisMaxRating`; it must be positive, explicitly verified, and have nonempty provenance. The UI cannot establish that verification; the producer must substantiate it. A rating above the axis is shown numerically with its bar hidden. Reference values beyond the axis are discarded. Missing or unverified axis hides all bars and reference marks and shows a compact axis-unavailable message in each row. Missing current rating retains the clearly percent-labelled existing current value, with no invented rating fill. An unknown cohort may show a neutral own rating bar when current rating and verified axis exist. `sampleCount` is a positive integer if supplied; no sample size is assumed. A producer must establish source rights and sampling validity separately.

`sourceStatus` accepts exactly the public string `"verified"` for reference min/mean/max, interval band, sample headline, and proximity tint. Missing status is treated as unverified. `"unverified"`, `"unavailable"`, `"invalid"`, unknown strings, and Secret values suppress all reference marks, interval band, and proximity tint; a valid own rating and axis may still show a neutral own bar. Status text remains available in the row tooltip. Verification of the rating axis and verification of the source are separate requirements.

The filled width locates own rating on the verified axis. Grey minimum and maximum ticks sit on different vertical sides of the track. A gold square with a short stem marks the arithmetic mean above the track; a tall white stroke marks own rating in the track, so all four coincident values remain distinguishable. The interval band sits behind the fill and extends above and below it only when both verified bounds are known. Minimum, numeric arithmetic mean, and maximum occupy three measured columns; the German mean label uses `Ø` when its full name exceeds the narrow column. A valid full min/mean/max range tints the own fill most strongly at the mean, symmetrically by absolute distance using the larger half span. Outside the observed range, or without a valid full range, the fill is neutral. Color encodes descriptive proximity only; it never suggests an optimum or higher-is-better rating. There is no animation or polling.

The panel keeps CharacterFrame's physical height and existing virtual-screen conversion. Hover text explains sample uncertainty, the arithmetic mean, rating cap provenance, and missing fields, and updates during an open row hover when a new snapshot renders. Native Default and Flat dark skins repaint the same widgets. The [preview](comparison-bars-preview.html) is an original browser mock with synthetic rating points and a synthetic cap; it is not addon data or in-game acceptance. It accepts `skin`, `locale`, `fixture`, and `size` query parameters and exposes `window.previewChecks` plus `#panel[data-checks]` for headless screenshot verification.

Integration needs: a separate provider/Core change must populate and substantiate `ratingComparison`. It must not place percent fields or unverified `GetCombatRating` values in this interface. The issue12 Standard selection styling is integrated alongside these bars; Flat keeps its existing colors and no selection underline. Tooltip refresh tracks its owner explicitly rather than relying on a mock-only GameTooltip.owner field.
