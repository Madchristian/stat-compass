# Offline cohort data contract

`StatCompass/Data.lua` is deliberately empty. The schema is a validation framework, **not** an authenticated provider or a license to ship data. See the [full source research](top50-eu-source-research.md) and [rights summary](provenance.md).

Schema 3 uses numeric `interface` (`120100` at the researched snapshot) **separately** from numeric `clientBuild` (`69933`). Runtime comparison uses `GetBuildInfo()` returns 4 and 2 respectively, plus `UnitLevel("player")`. The manifest has integer UTC epochs `collectedAt`, `observedAt`, `expiresAt`, an HTTPS `sourceURL`, and a reviewed `permission` reference. The unmodified source export is supplied separately; its SHA-256 is computed into `rawSHA256`. Text with control characters or surrogates is rejected before Lua 5.1 serialization.

Each cohort declares `region: "EU"`, `mode: "raid"` or `"mythic"`, spec ID, matching interface/build/level, `season`, `rankingMetric`, `difficulty`, `partition`, `unit: "percentPoints"`, `semanticKind: "masteryEffectPercent"`, `observedAt`, `selectedCount` and `validCount` equal to the number of observations, and 20 to 50 unique observations ordered by rank 1–n. The Blizzard generator ships 30 per spec. Each row repeats its region, mode, spec, interface, build, level, unit, semantic kind, and observation time. Each stat percentage must be finite and nonnegative; Crit is at most 100 because it is a probability. Mastery effect may exceed 100. Each row also carries raw combat ratings `critRating`, `hasteRating`, `masteryRating` and `versatilityRating` (finite, nonnegative). Ratings are compared only rating to rating within the same spec, build and level; nothing converts them to percent. A cohort `unit` other than `percentPoints` is still rejected. There is no invented 4000-rating cutoff.

Observation chronology is bounded twice: every row must be observed within the 24 hours ending at its cohort `observedAt`, inclusive, and no more than 30 days before dataset `collectedAt`, inclusive. Cohort `observedAt` equals the latest row observation; dataset `observedAt` equals the latest cohort observation. The builder and runtime both reject stale rows or inconsistent summaries. A provider may require a shorter observation age. These schema limits are not proof that a source is current or licensed.

The offline builder rejects future collection or observation timestamps, expired data, and an expiry more than 30 days after collection. The runtime requires finite integer `GetServerTime()`, rejects unknown time, future collection/observation, expiry at or before the current second, and exact build/interface mismatch. A provider's permitted cache life can be shorter than 30 days; the schema's maximum does not override it. The output carries source, selected/valid counts, observed/collection/expiry dates, and ranking metadata into the target object and panel tooltip. The target exposes, per stat, the arithmetic mean, the exact minimum and maximum, and the nearest-rank middle 50% band (ranks ⌈n/4⌉ and ⌈3n/4⌉) of the percentages, plus `target.rating[stat] = {mean, min, max}` for the ratings, and `sample = n`. These describe selected players; they are not an optimum.

The visible panel schedules one refresh at the validated expiry; hiding, a newer render, or a change in dataset identity, mode, or spec invalidates that callback. It does not poll while hidden. A shown tooltip is refreshed with the panel. Overflow-safe mean calculation keeps finite percentage inputs finite, and large or tiny nonzero display values use compact scientific notation. Each bar has separate current, minimum, and maximum numbers; unavailable values hide their corresponding fill or markers. The interface escapes WoW markup in displayed source, ranking metadata, and specialization names.

The bar axis uses a finite rounded upper bound above the larger known current or cohort maximum; a zero-only row uses an axis of one percent point. At extreme finite values where the next rounded bound would overflow, it uses the observed maximum. Minimum ticks extend above the track, maximum ticks below it, and the current tick crosses it, so coincident endpoints remain separately visible. Geometry changes redraw the cached bar state without reading live stats. The panel scales its own design units from CharacterFrame's physical height, matches its physical top and bottom when it fits the viewport, and uses a compact layout for shorter frames.

For an authorized future release, generate a candidate outside the addon first:

```powershell
.venv/Scripts/python.exe tools/build_data.py --manifest reviewed-cohorts.json --raw-source unmodified-source-export.json --output candidate-Data.lua
```

The source and rights review must establish an actual EU spec ranking, snapshot/stat semantic matching, collection and observation times, provider cache and distribution permission, attribution, raw-data retention/deletion, character status/deletion handling where required, and a way to revoke stale distributed archives. The Blizzard workflow in [blizzard-acquisition.md](blizzard-acquisition.md) produces such a candidate; replacing `StatCompass/Data.lua` stays a reviewed release step. Review all 50 ranks and hashes before replacing `StatCompass/Data.lua` in a new addon version. The game performs no network requests.
