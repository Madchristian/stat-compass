# Local Raider.IO acquisition evidence and limits

The [official Swagger](https://raider.io/swagger.json) publishes `GET https://raider.io/api/v1/client/character-rivals?region=eu&realm={realm}&name={name}&scope=region&specId={numericSpecId}`. Its description identifies the response as a specialization leaderboard window. `scope=region` is required because the endpoint defaults to realm scope. This is a Mythic+ selection, not a raid leaderboard or a measure of currently equipped stats.

`tools/providers/rio_rivals.py` uses only this HTTPS host and path, rejects redirects, caps each response at 256 KiB and each request at 10 seconds by default, and bounds retries and total wait after HTTP 429. It traverses from a public seed to rank 1, then down past rank 50. It validates region, scope, season path, class/spec, ordered finite scores, rank gaps, duplicate identities and overlap drift. A trailing numeric page in `fullRankingPath` is accepted. Anonymous rank slots count toward coverage, but the tool neither queries them nor exposes their synthetic names. A blocked walk fails closed. The result describes an **interval collection**, since the API provides no server snapshot token.

From the saved public Arcane windows gathered on 2026-10-02, local replay visited 26 windows and covered ranks 1–50 with rank 51 as a cutoff witness. Ranks 15, 38, 40 and 49 were hidden, so only 46 distinct public identities occupy the first 50. Strict 50-player input eligibility is false. Holy Paladin and Blood Death Knight had single-window probes only; all-spec coverage is unproved. The Codex sandbox initially blocked a fresh request at the local socket permission boundary. The orchestrator subsequently exercised the same provider outside that sandbox with one official HTTPS request and no retry: HTTP 200, validated EU Arcane ranks 1–5 with selfRank 1, observed at `2026-10-02T13:34:16.790126+00:00`. The parsed-and-reserialized local response SHA-256 is `755f4f9c4d3c5d12d379c94d2ca201eff083d2bc729f118618945ac7df63ee62` (not a hash of original wire bytes). Raw character-bearing output remains only in external scratch. This new single-window proof does not refresh the earlier complete walk.

Run a bounded local walk with an approved public seed, current season metadata and matching class/spec slugs:

```powershell
.venv/Scripts/python.exe tools/providers/rio_rivals.py --realm PUBLIC_REALM_SLUG --name PUBLIC_SEED_NAME --spec-id 62 --class-id 8 --class-slug mage --spec-slug arcane --season season-mn-2 --max-requests 60
```

The command prints only rank coverage/counts and never writes raw responses by default. `--raw-dir C:/Users/Christian/AppData/Local/hermes/cache/scratch/rio_probe/new-walk` optionally writes response JSON under scratch for local diagnosis. That material contains public character identities: keep it outside Git, release ZIPs and shared logs, delete it under applicable retention rules, and never use it to identify anonymous ranks. The season slug is an observed example, not a permanent setting. A 429 with a `Retry-After` beyond the remaining five-second default wait budget stops the walk.

The provider does not fetch Blizzard statistics or create `Data.lua`. The authenticated Blizzard public profile flow requires `BLIZZARD_CLIENT_ID` and `BLIZZARD_CLIENT_SECRET` through [client credentials OAuth](https://community.developer.battle.net/api/pages/content/documentation/guides/using-oauth/client-credentials-flow.json), followed by public profile, statistics, equipment, specializations and status endpoints under `https://eu.api.blizzard.com` with `namespace=profile-eu`. No authenticated payload has been inspected here; field units, stable identity joins, active-spec coherence and status/deletion handling remain blocked. Optional `RAIDER_IO_ACCESS_KEY` is a rate-limit credential, not redistribution permission.

Raider.IO's [terms](https://raider.io/terms-of-use) allow published API access with conditions, including attribution and restrictions on competing services and resale. Public access alone does not establish rights to ship a character-bearing addon dataset. Blizzard's [developer terms](https://www.blizzard.com/legal/a2989b50-5f16-43b1-abec-2ae17cc09dd6/blizzard-developer-api-terms-of-use) impose retention and character invalidation duties. Strict Top50 remains blocked by hidden identities, unverified Blizzard data, all-spec coverage, and rights/retention review.

`tools/release_gate.py` is a **local prerequisite and 120-hour due calculator**, not a network publisher or enabled schedule. Invoke `.venv/Scripts/python.exe tools/release_gate.py path/to/reviewed-state.json`. The reviewed JSON state requires UTC epoch `now`, `last_release: {"id":"...","published_at":1800000000,"channel":"data","verified":true}` (or `last_release: null` and `first_release_approved: true`), a full 40-character `approved_code_sha` matching `running_code_sha`, a season slug, `pending_unverified_publication: false`, and `quality` with `coverage`, `identities`, `blizzard_stats`, `rights`, `retention` and `readback` all set to true. The idempotency key derives from previous verified release ID, approved SHA and season. Missing or future clocks, a code-channel/unverified release, SHA mismatch and an unverified pending publication fail closed. The file must come from a trusted local review; this module does not independently inspect GitHub. A real publisher would still need serialized release discovery, draft upload and readback, public readback, recovery, cleanup and independent approval; none is implemented or activated.
